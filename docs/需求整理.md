# 包头市重点区域气象灾害监测预警平台需求整理

## 1. 结论

现有 `Laravel 13 + Filament 5 + Vue 3 + ECharts + CesiumJS` 适合作为平台的业务后台与展示端基础。Filament 适合快速建设设备、隐患点、预警、联系人、通知记录和权限管理；Vue 负责大屏和复杂交互；CesiumJS 负责 3D Tiles、设备点位和风险图层。

当前仓库属于可运行原型：已有设备、预警、用户角色和综合态势首页，但还没有真实采集链路、空间数据库、时序数据、通知网关和三维实景数据。

正式部署建议：PostgreSQL + PostGIS 作为业务与空间库，TimescaleDB 或 PostgreSQL 分区表保存高频时序数据，Redis 负责队列和缓存，MinIO 保存影像/模型/附件，Laravel Horizon/Reverb 负责异步任务和实时事件。SQLite 仅用于本地演示。

## 2. 业务域

## 3. 非功能指标

系统要求 7×24 小时运行、全年可用率不低于 99%、数据有效率不低于 98%、设备在线率目标不低于 95%、预警推送时延不高于 3 分钟；关键故障 30 分钟内恢复。三维端目标是 25km² 场景、200 个设备点位稳定 30fps。数据统一使用北京时间（UTC+8）和 CGCS2000；高频数据与业务数据按“时间 + 空间 + 设备 ID”联合检索。

这些指标不能靠当前单机 SQLite 原型直接满足，必须在部署阶段加入主备、队列、监控、备份和压力测试。

## 4. 分阶段建设

1. **后台基础（当前）**：权限、设备、隐患点、风险区、预警、联系人、通知策略、通知记录、审计。
2. **数据接入**：设备协议适配、设备心跳、数据质量、时序库和实时推送。
3. **指挥一张图**：PostGIS、真实 3D Tiles、图层开关、设备曲线、视频和洪水演进。
4. **智能分析与通知**：模型服务、风险推理、短信/语音/广播网关、回执和重拨。
5. **共享与验收**：API Key/签名、报表、备份容灾、168 小时稳定性测试、性能和安全测试。

## 5. 当前明确不应伪造的能力

真实气象“天擎”数据、运营商短信/语音、GNSS/雨量/水位实时数据、无人机 OSGB、卫星 InSAR、AI 模型、数字人和应急广播都需要外部账号、协议或数据文件。后台先提供配置、任务和结果承载能力，接入完成后再打开生产开关。
