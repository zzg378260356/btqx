# 天擎数据中转服务（music-proxy）使用说明

> 面向：需要取气象数据的下游系统、模型、同事
> 维护：包头市气象综合保障中心 · 张春雷（18004722048）
> 更新：2026-10-22 ｜ 实测环境：本机 172.18.134.92

## 一句话

天擎（CMADAAS/MUSIC）的账号、密码和 MD5 签名全部封装在这台服务器上，**调用方只要一个 API Key**，
用普通 HTTP GET 就能取到国家站/区域站观测、预警信号、闪电定位等数据，返回标准 JSON。

```
你的程序 ──HTTP GET + X-API-Key──▶ 172.18.134.92:10310 ──签名──▶ 天擎 10.62.90.120
                                        （本服务）
```

**不需要**：天擎账号、天擎密码、签名算法、内网 10.62 网段访问权限。

## 1. 接入信息

| 项 | 值 |
|---|---|
| 服务地址 | `http://172.18.134.92:10310` （内网/专网；本机亦可 `http://127.0.0.1:10310`）|
| 协议 | HTTP GET，返回 JSON（UTF-8）|
| 鉴权 | API Key，三选一：请求头 `X-API-Key` / 请求头 `Authorization: Bearer` / URL 参数 `?key=` |
| Key 申请 | 联系维护人；服务端支持多把并行，按把单独撤销，互不影响 |
| 速率限制 | 无硬限制；相同查询 120 秒内走缓存，请勿高频重复拉同一时次 |
| 可用性 | `/health` 免鉴权，可做存活探测 |

> ⚠️ 本服务只在内网提供，**未对公网开放**。外单位接入需先连入气象内网 / VPN。

## 2. 30 秒上手

**① 浏览器直接看**（把 `<KEY>` 换成你的 key）：

```
http://172.18.134.92:10310/health
http://172.18.134.92:10310/v1/presets?key=<KEY>
http://172.18.134.92:10310/v1/surf?time=20261022040000&key=<KEY>
```

**② Python（标准库，无需装包）**：

```python
import urllib.parse, urllib.request, json

BASE, KEY = "http://172.18.134.92:10310", "<KEY>"

q = urllib.parse.urlencode({"time": "20261022040000"})   # 区域自动站，UTC 整点
req = urllib.request.Request(f"{BASE}/v1/surf?{q}", headers={"X-API-Key": KEY})
with urllib.request.urlopen(req, timeout=180) as r:
    d = json.loads(r.read().decode("utf-8"), strict=False)   # strict=False 见第 8 节坑 4
print(d["rowCount"], d["DS"][0])
```

**③ curl**：

```bash
curl -H "X-API-Key: <KEY>" "http://172.18.134.92:10310/v1/presets"
```

**④ 前端 / JS**（服务已开 CORS `Access-Control-Allow-Origin: *`）：

```js
const r = await fetch("http://172.18.134.92:10310/v1/surf?time=20261022040000",
                      {headers: {"X-API-Key": "<KEY>"}});
const d = await r.json();
```

## 3. 端点一览

| 端点 | 作用 | 必填参数 |
|---|---|---|
| `/health` | 健康检查 + 上游连通性与耗时（**免鉴权**）| — |
| `/` | 浏览器用法页 | — |
| `/v1/presets` | 预设清单（三个预设的 dataCode/接口/要素）| — |
| `/v1/query` | **通用转发**：天擎原生参数原样带上，任何数据集都能走 | `dataCode`、`interfaceId` |
| `/v1/alerts` | 预警信号（发布/变更/解除）| `begin`、`end` |
| `/v1/surf` | 地面区域自动站（全国 2.2 万站）| `time` |
| `/v1/lightning` | 闪电定位（默认包头范围）| `begin`、`end` |

### 3.1 `/v1/alerts` 预警信号

```bash
GET /v1/alerts?begin=20261022000000&end=20261022235959&sender=包头市气象台&skip_release=1
```

| 参数 | 说明 |
|---|---|
| `begin` / `end` | **14 位** `YYYYMMDDHHMMSS`，UTC（= 北京时 − 8 小时）|
| `sender` | 可选，模糊匹配发布单位，如 `包头市气象台`（旗县台名不同，用 `固阳县气象台` 之类；不确定就别传，拉全国再本地过滤）|
| `skip_release` | 可选，`1` = 去掉解除报文（`msg_type=2`）|
| 附带返回 | 过滤生效时多一个 `filteredBy` 字段，`rowCount` 已按过滤后重算 |

> 上游该数据集**每小时 :05 批量入库**，所以发布时刻到你能查到，滞后 0～60 分钟不等。
> 抢时效请用中央气象台公开接口；要归档/统计/全字段用这里。

### 3.2 `/v1/surf` 地面区域自动站

```bash
GET /v1/surf?time=20261022040000
```

返回全国约 **22,440** 站 × 8 要素（≈3.2 MB / 单时次）：

`Station_Id_C, Station_Name, Lat, Lon, TEM, PRE_1h, WIN_S_Avg_2mi, WIN_D_Avg_2mi`

- 只要包头：本地按 `Station_Id_C` 前 5 位（`534xx`～`535xx` 一带）或按经纬度矩形过滤，服务端不提供站号过滤。
- 要素不够用 `&elements=...` 覆盖（例如加 `RHU,PRS,VIS,Station_Name`）。
- **降水用 `PRE_1h`，`PRE` 恒缺测**；区域站分钟级只有 `TEM`、`PRE_1h` 可用，`RHU`/`PRS` 为 `999999`。

### 3.3 `/v1/lightning` 闪电定位

```bash
GET /v1/lightning?begin=20261022000000&end=20261022235959
```

默认矩形 = 包头（`MINLAT=40.15&MAXLAT=42.85&MINLON=109.20&MAXLON=111.50`），可覆盖；
全国可给 `MINLAT=18&MAXLAT=54&MINLON=73&MAXLON=135`。
要素名是 `Lat`/`Lon`（不是 `Lit_Lat`/`Lit_Lon`）。全国 24h 全量约 3 万条 / 10 MB / 2 秒。

### 3.4 `/v1/query` 通用转发

任何天擎能力都能走这条，参数与天擎原生一致（服务端自动补 `serviceNodeId/userId/timestamp/nonce/sign`）：

```bash
# 国家站小时观测
GET /v1/query?dataCode=SURF_CHN_MUL_HOR&interfaceId=getSurfEleByTime
              &times=20261022040000&elements=Station_Id_C,Lat,Lon,TEM&dataFormat=json
```

常用 `dataCode × interfaceId`：

| dataCode | 内容 | interfaceId | 规模 |
|---|---|---|---|
| `SURF_CHN_MUL_HOR` | 国家站小时观测 | `getSurfEleByTime` | 全国 369 站 |
| `SURF_CHN_MUL_MIN` | 区域自动站 | `getSurfEleByTime` | 全国 22,440 站 |
| `UPAR_LIGHT_ADTD_MUL` | 闪电定位 ADTD | `getUparEleInRectByTimeRange` | 24h ≈3 万条 |
| `DISA_CHN_ALERT_INFO` | 预警信号 | `getDisaEleByTimeRange` | 全国，按天 20～200 条 |
| `SURF_GF_NM_MUL_HOR` | 内蒙古光伏辐射 | `getRadiEleByTimeRange` | 22 站（**只到 2025-01**，已停更）|

## 4. 时间口径（最容易错）

- **全部 UTC**。北京时 12:00 = `20261022040000`。
- 一律 **14 位** `YYYYMMDDHHMMSS`。写 12 位（`202610220400`）会被当无效 —— 本服务会直接返回 400，不给你 0 行的假象。
- 传未来时次 → 0 行（整点数据有 10～30 分钟入库滞后）。
- 预警的 `Datetime` 与 `UPDATE_TIME`（入库时刻）都是**北京时**字符串，与查询参数口径不同，别混用。

## 5. 返回结构

上游原样透传，标准形态：

```json
{
  "returnCode": "0",
  "returnMessage": "Query Succeed",
  "rowCount": "21",
  "colCount": "17",
  "DS": [ { "字段名": "值", ... }, ... ]
}
```

真实样例（`/v1/alerts`，2026-10-22 全国前 1 条）：

```json
{
  "alert_id": "15252341600000_20261022080326",
  "sender": "苏尼特左旗气象台",
  "msg_type": "0",
  "event_type": "自然灾害—>气象灾害—>大风",
  "severity": "2",
  "headline": "苏尼特左旗气象台发布大风黄色预警[III级/较重]",
  "areadesc": "苏尼特左旗,查干敖包镇,巴彦乌拉苏木,...",
  "Datetime": "2026-10-22 08:03:26",
  "UPDATE_TIME": "2026-10-22 09:05:00"
}
```

要点：`returnCode` 是**字符串** `"0"`；所有值都是字符串类型，数值自己转；
**缺测不是空串而是 `999999`**（或空串，取决于字段/数据集）。

## 6. HTTP 状态与错误码

| HTTP | 含义 | 处理 |
|---|---|---|
| 200 | 成功（`returnCode="0"`）| — |
| 400 | 参数不足/格式不对（缺 `dataCode`、时间不是 14 位等）| 看 `returnMessage` 改参数，**别重试** |
| 401 | key 缺失或错误 | 换 key，别重试 |
| 404 | 端点不存在 | 查端点表 |
| 502 | 上游失败或超时（响应头 `X-Upstream-HTTP` / `X-Elapsed` 给细节）| 可重试 1～2 次；持续 502 时联系维护人 |

上游 `returnCode`（服务会原样透传）：

| 值 | 含义 |
|---|---|
| `0` | 成功 |
| `-1002` | 无数据（该时次没入库 / 时段没记录）|
| `-2001` | 该数据集不绑这个 interfaceId → 换接口 |
| `-3002` | 缺参数（说明接口对，补参数）|
| `-3003` | 参数名/值不合规 |
| `-4005` | 签名/账号问题（**调用方遇不到**，只会在服务端日志出现）|

## 7. 服务行为

| 项 | 值 |
|---|---|
| 缓存 | 相同查询 120 秒内直接返回，响应头 `X-Cache: hit`；`&nocache=1` 强刷 |
| 重试 | 上游超时/5xx 自动重试 2 次，单次超时 120 秒 |
| 响应上限 | 24 MB（超了返回 502 + `-9001`）|
| 并发 | 多线程处理，互不阻塞 |
| 记录 | 每次请求记一条日志，含来源 IP 与 key 标签，便于溯源 |

## 8. 十个坑（都是实测踩过的）

1. **时间必须是 14 位**。12 位会被上游静默返回 0 行（本服务现已拦成 400）。
2. **本地参数不透传**：`sender`、`skip_release`、`key`、`nocache` 只在本服务生效；自己乱加其它参数会被上游当错、甚至静默 0 行。
3. **中文参数要 URL 编码**。`sender=包头市气象台` 在 Python `urllib` 里必须 `urlencode`，否则本地就抛 `UnicodeEncodeError`。
4. **JSON 里可能有原始控制字符**（预警正文带换行/TAB）→ 解析一律 `json.loads(raw, strict=False)`；严格模式会整包报 `Invalid control character`。兜底：`re.sub(r"[\x00-\x08\x0b\x0c\x0e-\x1f]", " ", raw)` 再解。
5. **elements 里写一个不存在的字段名 → 整个查询静默返回 0 行**（HTTP 200、不报错）。加字段要一个一个试。
6. **`limitCnt` 省略才是全量**；写个很大的数反而要重签、也别指望它限制。
7. **预警大查询会 502**：7 天 × 全字段一次拉会超时；按天切分 + 重试（同一天第一次 90 秒失败、第二次 4 秒成功是常态）。
8. **区域站风速/辐射缺测多**：`WIN_S_Gust_Max` 全国覆盖率低，包头顶多 76/154 站有值 —— 出图请标“有效 N/M 站”，别让用户以为全市只有几十个站。
9. **没有站号过滤参数**（站 API 那套不适用这里）：要单站就拉整时次后本地筛，或 1 分钟窗口 + 正则从原文抠。
10. **不要把 key 写进前端公开代码**：JS 直连只适用于内网可信页面；对外发布请走后端代理。

## 10. 边界

- 本服务**只做转发**，不加工数据：字段口径、缺测标记、入库滞后都由天擎决定。
- 格点场/雷达基数据等**文件类**数据不走这里，走数据湖挂载 `/CMADAAS`（`DATA/{SURF,NAFP,RADA,QPE,...}`）。
- 服务跑在用户态 systemd（`Restart=always`），随登录会话常驻；主机重启后自动恢复。
